# Сравнение порядка загрузки — этап 4

Проверено 25.10.2026: Maven 3.9.11, OpenJDK 21,
maven-dependency-plugin 3.8.1, `junit:junit:4.13.2` из Maven Central.
Исходные результаты сохранены в `comparison/junit-report.txt`,
`comparison/junit-resolved.txt`, `comparison/junit-tree.txt` и TGF.

Алгоритм приложения использует нерекурсивный DFS postorder:

```text
org.hamcrest:hamcrest-core:1.3 -> junit:junit:4.13.2
```

В фактическом выводе `mvn dependency:resolve -DincludeScope=runtime`
зависимости перечислены в обратном порядке:

```text
junit:junit:jar:4.13.2:compile
org.hamcrest:hamcrest-core:jar:1.3:compile
```

Состав пакетов и ребро JUnit → Hamcrest полностью совпали с Maven.
Расхождение порядка объясняется разными операциями: приложение строит
план загрузки «зависимости раньше потребителей», Maven перечисляет
разрешённые артефакты, начиная с прямой зависимости consumer-проекта.
JAR можно скачать до его зависимостей, поэтому такой порядок корректен.
Это сравнение именно с порядком в выводе штатной операции разрешения,
а не измерение времени сетевых скачиваний. Время скачиваний дополнительно
зависит от кеша, сети и параллельности и не задаёт топологический порядок.

Нейтральный `demo:comparison:1` нужен только для вызова Maven и удаляется
при сравнении. Анализатор рассматривает выбранный пакет как зависимость
внешнего потребителя; его test/provided/optional зависимости не включаются.

## Тестовые репозитории

| Конфигурация | Полученный порядок |
| --- | --- |
| chain | D, C, B, A |
| diamond | D, B, C, A; D ровно один раз |
| single | A |
| shorter, глубина 3 | F, E, D, B, C, A |
| depth-zero | A |
| depth-one | B, A |
| filtered, исключение B | A |
| cycle | Ошибка: A → B → C → A; полного порядка нет |

Порядок относится только к графу после ограничения глубины и фильтрации.
На четвёртом этапе: `./scripts/demo_graphs.sh`.
На финальном этапе временный вывод порядка заменён визуализацией;
проверки алгоритма сохраняются в `tests/test_order.py`.
