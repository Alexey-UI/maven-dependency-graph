# Граф зависимостей Maven — вариант 20

Практическая работа № 2 по конфигурационному управлению. Python 3.11+.
Источники требований: сборник ИКБО-10-25, страницы 4–7 и 65–67.
Зависимости будут извлекаться самостоятельно из POM, без менеджеров
пакетов и библиотек разрешения зависимостей.

## Установка и запуск

Сборка Python-проекта не требуется. Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
./run.sh examples/maven.yaml
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=src .venv/bin/python scripts/demo_config_errors.py
```

`run.sh` принимает только путь к YAML и `--help`. Все настройки берутся
из YAML; пути внутри него считаются относительно самого файла.
Для другого интерпретатора: `PYTHON=python3 ./run.sh examples/maven.yaml`.
Ошибки завершают программу с кодом 1; ошибки CLI — с кодом 2.

## Настройки

Все восемь ключей обязательны. Неизвестные и повторяющиеся ключи запрещены.

| Ключ | Значение |
| --- | --- |
| `package` | Maven `groupId:artifactId`; в тестовом режиме имя `[A-Z]+` |
| `repository` | Базовый HTTP(S) URL Maven или путь к тестовому YAML |
| `test_mode` | YAML boolean `true` / `false` |
| `version` | Непустая строка конкретной версии; диапазоны не поддержаны |
| `output` | Путь к изображению `.png` |
| `ascii_tree` | Вывод ASCII-дерева: `true` / `false` |
| `max_depth` | Целое число ≥ 0; корень имеет глубину 0 |
| `filter_substring` | Строка; пустая отключает исключение по подстроке |

## Этапы

1. YAML-конфигурация: вывод восьми параметров в виде `ключ=значение`,
   проверка типов, значений и ошибок чтения; демонстрация всех ошибок.

2. Получение прямых зависимостей Maven из POM заданной версии.
   Временный вывод настроек этапа 1 заменён списком зависимостей.

## Интерпретация Maven POM

Модуль `maven.py` получает POM через `urllib`, `pom.py` разбирает XML
через `xml.etree.ElementTree`. Поддержаны пространства имён, родительские
POM, свойства `${...}`, наследование зависимостей, dependencyManagement
и импорт BOM. Модели кешируются на время запуска. HTTP-таймаут — 30 с,
размер POM — до 5 МБ; ошибки HTTP/XML/свойств сообщаются пользователю.

Рассматривается runtime-граф: scope compile/runtime без optional.
Test/provided/system не распространяются потребителю и пропускаются.
Профили, SNAPSHOT metadata, диапазоны версий и разрешение конфликтов
nearest-wins не реализованы. Exclusions, classifier и зависимости
не-JAR в анализируемом графе вызывают явную ошибку. Это учебный анализатор,
не полная реализация effective POM Maven.

Правила scope и mediation сверены с
[документацией Maven](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html).

3. Нерекурсивный DFS, ограничение глубины, фильтр подстроки и циклы.
   Временный список прямых зависимостей этапа 2 заменён графом.

## Тестовый репозиторий и обход

Формат файла `A: [B, C]`, `B: []`, `C: []` (каждый ключ на своей строке).
Имена — заглавные латинские буквы; все упомянутые узлы нужно объявить.
Версия из конфигурации присваивается всем тестовым узлам. Повторы ключей,
рёбер и неизвестные зависимости отклоняются. Готовые примеры:

```sh
./run.sh examples/chain.yaml
./run.sh examples/diamond.yaml
./run.sh examples/cycle.yaml
./run.sh examples/single.yaml
./run.sh examples/shorter.yaml
./run.sh examples/depth-zero.yaml
./run.sh examples/depth-one.yaml
./run.sh examples/filtered.yaml
PYTHONPATH=src .venv/bin/python scripts/check_quality.py
```

Глубина 0 оставляет корень, 1 — только прямые зависимости. Узлы на границе
не запрашиваются. Исключённый по подстроке узел не попадает в граф и
не обходится; исключение корня — ошибка. Фильтр регистрозависимый.
Пустая строка фильтра отключает его. DFS использует явный стек, кеш и
лучшую достигнутую глубину: узел, найденный по более короткому пути,
расширяется снова. Циклические рёбра сохраняются, обход завершается.
Порядок рёбер соответствует порядку зависимостей в исходном файле.
