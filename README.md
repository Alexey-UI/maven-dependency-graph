# Граф зависимостей Maven — вариант 20

Практическая работа № 2 по конфигурационному управлению, Python 3.11+.
Требования: сборник ИКБО-10-25, страницы 4–7 и 65–67.
Инструмент самостоятельно получает POM заданной версии, строит граф
нерекурсивным DFS и сохраняет Mermaid и PNG. Настройки — только YAML.
Менеджеры пакетов и библиотеки разрешения зависимостей в приложении
не используются: получение POM — `urllib`, разбор XML — `ElementTree`.

## Установка и запуск

Сборка Python-проекта не требуется. Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
```

Для PNG установите Node.js 22+ с https://nodejs.org/, затем:

```sh
./scripts/setup_renderer.sh
./run.sh examples/maven.yaml
```

Скрипт устанавливает Mermaid CLI 11.12.0 в `.tools/mermaid/`. На macOS
используется установленный Google Chrome, если он есть; иначе Puppeteer
скачивает свой браузер. На Linux могут потребоваться системные библиотеки
Chrome. Инструкция CLI — [Mermaid CLI](https://github.com/mermaid-js/mermaid-cli).
Сам анализ графа написан на Python; Node/Chrome нужны для отрисовки PNG.

`run.sh` принимает путь к YAML либо `--help`. Относительный путь к YAML
считается от текущего каталога; пути внутри YAML — от каталога этого файла.
Запуск из другого каталога поддержан. По умолчанию используется `.venv`;
другой интерпретатор: `PYTHON=python3 ./run.sh examples/maven.yaml`.
Локальные Node.js в `.tools/node-*/bin` и Mermaid CLI подхватываются
скриптами автоматически, также поддержаны установленные в PATH.

## Настройки

Все восемь ключей обязательны. Неизвестные и повторяющиеся ключи запрещены.
Версию записывайте строкой в кавычках. Пример `examples/maven.yaml`:

```yaml
package: junit:junit
repository: https://repo.maven.apache.org/maven2
test_mode: false
version: '4.13.2'
output: ../generated/junit.png
ascii_tree: true
max_depth: 10
filter_substring: ''
```

| Ключ | Значение |
| --- | --- |
| `package` | Maven `groupId:artifactId`; в тестовом режиме имя `[A-Z]+` |
| `repository` | Базовый HTTP(S) URL Maven или путь к тестовому YAML |
| `test_mode` | YAML boolean `true` / `false` |
| `version` | Строка конкретной версии; диапазоны не поддержаны |
| `output` | Путь к изображению `.png`; каталоги создаются автоматически |
| `ascii_tree` | Вывод ASCII-дерева: `true` / `false` |
| `max_depth` | Целое число ≥ 0; корень имеет глубину 0 |
| `filter_substring` | Регистрозависимая строка; пустая отключает фильтр |

## Возможности и результаты

Программа сохраняет PNG и текстовый Mermaid в соседний файл `.mmd`.
PNG создаёт официальный Mermaid CLI из сохранённого текста диаграммы.
В Git изображения не хранятся: PDF запрещает бинарные файлы.
Если рендер завершился ошибкой, Mermaid остаётся доступен, старый PNG
не заменяется. Код завершения: 0 — успех, 1 — ошибка, 2 — ошибка CLI.

При `ascii_tree: true` дополнительно выводится, например:

```text
junit:junit:4.13.2
\-- org.hamcrest:hamcrest-core:1.3
```

DFS использует явный стек, кеш зависимостей и лучшую достигнутую глубину.
Глубина 0 оставляет корень, 1 — прямые зависимости. На границе POM
не запрашивается. Пакет, исключённый фильтром, не включается и не обходится;
исключение корня — ошибка. Фильтрация применяется к имени без версии.
Узел, найденный по более короткому пути, расширяется повторно: так не
теряются доступные в пределах глубины зависимости. В объединённом графе
возможны и более длинные пути к общим узлам.

Циклы сохраняются в графе. В ASCII-дереве возврат к предку отмечается
`[cycle]`, повторная общая зависимость — `[shared]`; ветка дальше не
разворачивается. Диаграммы используют одно объявление каждого узла.

Ошибки YAML, типов и значений параметров, чтения файлов, отсутствующего
пакета, HTTP, XML, свойств POM и запуска Mermaid сообщаются в stderr.
HTTP-таймаут — 30 с, размер POM — до 5 МБ, таймаут Mermaid — 120 с.

## Примеры и демонстрации

```sh
./scripts/demo_visualization.sh
./scripts/demo_graphs.sh
./run.sh examples/no-ascii.yaml
PYTHONPATH=src .venv/bin/python scripts/demo_config_errors.py
```

Три реальных пакета: JUnit 4.13.2, Commons Text 1.12.0, SLF4J API 2.0.16.
Результаты и сравнение со штатным Maven описаны в
[docs/visualization.md](docs/visualization.md); Mermaid доступен прямо там.
PNG генерируются локально в `generated/`.

Тестовый репозиторий — YAML-словарь с заглавными латинскими именами:

```yaml
A: [B, C]
B: [C]
C: []
```

Все упомянутые узлы должны быть объявлены; повторы ключей/рёбер запрещены.
Версия конфигурации присваивается всем тестовым узлам. В `examples/` есть
`chain`, `diamond`, `cycle`, `single`, `shorter`, `depth-zero`, `depth-one`,
`filtered`, `no-ascii`: конфигурации для цепочки, общей зависимости,
цикла, листа, более короткого пути, пределов глубины и фильтрации.

## Проверки

```sh
./scripts/check.sh
RUN_RENDER_TESTS=1 ./scripts/check.sh
```

Первый запуск проверяет логику без сети и браузера. Во втором дополнительно
создаются реальные PNG циклического графа с включённым и выключенным ASCII.
`check_quality.py` проверяет Python-строки ≤ 80 символов, функции ≤ 40 строк,
файлы ≤ 1000 строк, аргументы ≤ 7, сложность Radon ≤ 10, docstring,
отсутствие числовых литералов в сравнениях и комментариев вместо docstring,
PEP 8 через pycodestyle и `git diff --check`.

Прямые команды без скрипта:

```sh
PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v
PYTHONPATH=src .venv/bin/python scripts/check_quality.py
```

## Проверка штатным Maven

Maven нужен только независимому проверочному скрипту, а не приложению.
Нужны JDK и Maven в PATH, либо переменная `MVN=/путь/к/mvn`:

```sh
PYTHONPATH=src .venv/bin/python scripts/compare_maven.py \
    examples/maven.yaml examples/commons-text.yaml examples/slf4j.yaml
```

Скрипт создаёт нейтральный consumer-POM в `generated/comparison/`, вызывает
официальный maven-dependency-plugin 3.8.1: `dependency:tree` (text/TGF)
и `dependency:resolve`. Сравнивает полные координаты, узлы и рёбра.
Кеш изолирован в `generated/maven-cache/`. Для сверки используйте Maven
Central, `max_depth: 10` и пустой фильтр: Maven-скрипт их не применяет.
Фактические результаты сохранены в `docs/comparison/`.
Различие порядка разрешения объяснено в [docs/load-order.md](docs/load-order.md).

## Интерпретация Maven POM

Поддержаны XML с namespace и без него, родительские POM, свойства `${...}`,
наследование зависимостей, dependencyManagement и импорт BOM. Модели
кешируются на время запуска. Анализируется runtime-граф пакета как
зависимости внешнего потребителя: compile/runtime без optional.
Test/provided/system зависимости не распространяются потребителю.

Профили, SNAPSHOT metadata, диапазоны версий и разрешение конфликтов
nearest-wins не реализованы. Разные версии представлены разными узлами.
Exclusions, classifier и не-JAR зависимости в анализируемом графе вызывают
явную ошибку. Наследованные managed-версии раскрываются в контексте
родительского POM; переопределение этих свойств ребёнком не моделируется.
Это учебная реализация, ограничения не влияют на три проверенных примера.

Правила scope и mediation описаны в
[документации Maven](https://maven.apache.org/guides/introduction/introduction-to-dependency-mechanism.html).

## Устройство исходного кода

Все функции и методы снабжены docstring. Основные интерфейсы:

| Модуль в `src/dependency_graph/` | Назначение |
| --- | --- |
| `__main__.py` | `main`: CLI, загрузка настроек, анализ, вывод и ошибки |
| `config.py` | `Config`, `load_config`, проверки типов/значений/репозитория |
| `yaml_file.py` | `load_yaml`, `UniqueLoader`: UTF-8 YAML без повторов ключей |
| `model.py` | `Package`: координаты и версия; `Pom`: данные effective POM |
| `pom.py` | XML, свойства, строки зависимостей и их ключи |
| `maven.py` | HTTP, URL POM, effective model, родители, BOM, зависимости |
| `test_repository.py` | Загрузка, валидация и зависимости тестового графа |
| `graph.py` | `build_graph`: DFS; фильтр; текстовое представление рёбер |
| `order.py` | `load_order`: порядок загрузки и диагностика циклов этапа 4 |
| `visualize.py` | Mermaid, нерекурсивное ASCII-дерево, рендер и сохранение PNG |

`tests/` — модульные и включаемые интеграционные тесты.
`scripts/` — демонстрации, установка рендера, проверки и сравнение с Maven.
`examples/` — YAML-конфигурации и тестовые репозитории.
`docs/` — текстовые свидетельства сравнений и примеры Mermaid.

## Пять этапов в истории

1. `feat(config)` — YAML, восемь параметров, ошибки каждого параметра.
   Только на этом этапе выводятся настройки в формате ключ–значение.
2. `feat(maven)` — прямые зависимости конкретной Maven-версии.
   Только на этом этапе они выводятся отдельным списком.
3. `feat(graph)` — DFS без рекурсии, глубина, фильтр, циклы, тестовый режим.
4. `feat(order)` — временный вывод порядка загрузки, сравнение с Maven,
   демонстрации и объяснение различий. Алгоритм сохранён как функция.
5. `feat(visualization)` — Mermaid → PNG, ASCII и три реальных примера,
   сравнение графов с Maven. Временные выводы этапов 1, 2 и 4 убраны.

У каждого этапа свой подробный Conventional/Scoped Commit и тег `stage-N`.
PDF задания, PNG, кеши, архивы, виртуальное окружение и настройки редакторов
исключены через `.gitignore`.
